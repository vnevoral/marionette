# Glossary

| Term                                   | Description                                                                                                                                                                                                                                                                                                 |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Action Card**                        | A configurable unit on the dashboard grouping a primary action, a status action and metadata (name, icon, description).                                                                                                                                                                                     |
| **Action**                             | Definition of a command/process run on the host (shell command, arguments, timeout, env) incl. rules for evaluating the result (exit code, output).                                                                                                                                                         |
| **Status action / Health check**       | An action of the same type as the primary action, whose purpose is to find out the current state of the entity the primary action affects (e.g. `ping` after `Wake-on-LAN`).                                                                                                                                |
| **Card state**                         | A derived state (e.g. `unknown`, `ok`, `fail`, `running`) computed from the last result of the status action.                                                                                                                                                                                               |
| **State change history**               | A chronological history of actual transitions of the card state including start and end or duration; repeated checks without a change are not stored.                                                                                                                                                       |
| **Host**                               | The machine on which the Marionette instance runs and on which the configured actions are actually executed (Raspberry Pi / Ubuntu server).                                                                                                                                                                 |
| **Config store**                       | An in-memory structure holding all action cards and actions at runtime, backed (persisted) to a single configuration file (JSON).                                                                                                                                                                           |
| **Dashboard**                          | The main screen of the web UI showing all action cards and their state.                                                                                                                                                                                                                                     |
| **Run**                                | One specific run of an action incl. captured output, exit code, time and the resulting evaluation.                                                                                                                                                                                                          |
| **Standard polling interval**          | The regular interval of automatic execution of a card's status action, if enabled for the card (default 60 s).                                                                                                                                                                                              |
| **Fast polling (fast polling window)** | A temporarily shorter polling interval of the status action (default 10 s for 120 s) activated right after the primary action is invoked, to catch the state change sooner; after the window elapses the card returns to the standard interval. It activates only if the card has standard polling enabled. |
| **Forced termination**                 | Automatic termination (kill) of an action process by the execution engine after its `TimeoutSec` expires, so that no unfinished process is left hanging.                                                                                                                                                    |
