After **Run action**, a card no longer shows Problem just because its status
check has not caught up yet. It shows **Waiting** until a status check
confirms the action or the fast polling window ends.

## Highlights

- **Waiting state.** On a card with fast polling, **Run action** puts the
  card into **Waiting** (blue timer badge) on every open screen.
  - Scheduled status checks pause while the action is queued or running.
    When it finishes successfully, the fast polling window starts.
  - A successful check ends the wait at once and the card becomes
    Healthy.
  - A check that fails or times out during the window changes nothing
    and is not added to the status history; the next check is awaited.
  - If the window ends without a successful check, the last check
    decides, normally Problem, and only then is a change recorded.
  - A primary action that fails or times out is an error: the wait ends
    at once and no fast polling window starts. Set the action's timeout
    so that it always finishes and returns its exit code.
  - Waiting is not saved: after a restart the card shows its last
    confirmed state. **Run action** stays available while the card waits.
- Cards without fast polling or without a status check behave as before.
- **API clients:** the status of a card can now be `waiting`, with a new
  field `waitingUntil` (end of the wait, RFC 3339). A client that accepts
  only `unknown`, `ok` and `fail` should handle the new value. The status
  history never contains `waiting`.
