Marionette 2.0 has a new look. The UI no longer uses PrimeVue: it is built
from Marionette's own components on [Reka UI](https://reka-ui.com) with
[Lucide](https://lucide.dev) icons, and everything is MIT or ISC licensed.
Screens keep their layout. The version is a major one because card icons are
now stored under new names.

## Highlights

- A refreshed look: a quieter palette, soft status badges, layered card
  shadows, a sticky header with pill navigation and the system font.
- A new set of Lucide icons for cards, including router, printer, hard
  drive, Wi-Fi, TV, light, camera, power, network and processor.
- The card editor has **Cancel** and **Save card** in the page header, as
  on Card Detail, and the form sits in one centred column.
- New select, switch, toast and confirmation dialog, with keyboard
  support and screen reader labels. Toasts pause while you hover or focus
  them and can be closed.
- On phones narrower than 24 rem, the stacked header buttons keep their
  full height.
- The UI loads faster: the JavaScript bundle is about a quarter smaller
  (152 kB → 114 kB gzip).

## Breaking changes

- **Card icons are icon names.** A card's `icon` is now a name such as
  `house`, `server` or `hard-drive` instead of a PrimeIcons class such as
  `pi pi-home`. The API rejects the old form with `422`.
  - Your configuration still loads. A card with an old or unknown icon
    shows a **ghost** icon on the dashboard.
  - In the card editor such a card shows **Unavailable icon** and "This icon
    is no longer available. Choose a new one." It can be saved once you
    pick a supported icon.
  - Scripts and other API clients that send `icon` have to send a name
    from the list in the editor. The rule is lowercase letters and digits
    separated by single dashes, at most 64 characters.

## Upgrading

Install the release as usual (README, "Installing the latest release").
Then open each card with a ghost icon, choose a new icon and save.

## Under the hood

- Releases now carry these hand-written notes; a tag without
  `docs/releases/<tag>.md` fails before the build.
- CI runs `govulncheck` in the backend job, a tag produces one release run
  even if GitHub starts two, and builds use the latest Go patch release.
- Dependabot watches the major versions of `reka-ui` and `@lucide/vue`
  instead of PrimeVue.
